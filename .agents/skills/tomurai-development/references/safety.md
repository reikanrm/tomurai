# プライバシー・課金・運用の否定試験

変更箇所に該当する項目だけを具体的な受入試験へ落とす。以下は製品SSOTの代替ではない。

- actor、本人/ノートowner、回答者、payer、consent giver、corporate approverを混同しない。家族に参加しただけで他人のノート、心の状態、問い合わせを見せない。法人/専門家の管理権限から本文を開示しない。
- サーバー認可とAPI projectionで非公開データを除外する。モザイク、disabled、開発権限切替、ローカルのモデル関数をアクセス制御の完成としない。他グループ・他owner・失効・撤回・ID改変を拒否する試験を用意する。
- 生前ノートの代理入力では「入力担当の承認」「内容の確定」「他人への共有」を別に読む。未決の権限、承認できない人の例外、死後開示を推測しない。所属会社へ本文を見せない。
- 招待・人数変更・契約者変更・ケース作成から無承認の請求を発生させない。webhookの重複/遅延/順序逆転、失効/取消、枠の二重加算、無料表示件数の補充を試す。カード情報を保存しない。
- 実通知/専門家への送信は現在有効な同意・対象・権限と配信直前の再確認が必要。撤回、重複、再試行、quiet hours、失敗を扱う。単なる外部Mapsリンクを問い合わせの送信証拠にしない。
- 相続の期限・任意の儀式・ケア文言は一次出典と監修状態を分ける。死亡日+90日など未承認の自動期限、診断、感情の決めつけを追加しない。最新法令/ストア規定は現在の一次資料を確認する。
- 合成データのみ。氏名、住所、遺産、相談文、心の状態、招待token、鍵をプロンプト/テストfixture/ログ/スクリーンショット/チケットへ出さない。必要なダミーは実在と混同しない。エラーの収集も同様。
- インフラの予算・環境分離・監視・復旧・削除はGの証拠で判断する。作成済みGCP projectはリソース作成や月額費用の承認ではない。OS/認証/秘密設定を恒久的に緩めない。

認証・保存・権限・配信など未接続の層があれば、動く層だけを示し、未接続票と公開を止めるゲートを証跡へ残す。否定試験も成功画面だけのスクリーンショットで置き換えない。
