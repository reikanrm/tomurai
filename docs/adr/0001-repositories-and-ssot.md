# ADR-0001 リポジトリと正本の分離

- 日付：2026-09-26
- 状態：採用
- 決定者：テックリード・會田 純一朗
- 対応：TOM-22、TOM-25

## 背景

プロダクトのmainをPOがモックに使用している。開発とPOの作業を混ぜず、非開発者が理解しやすい仕様・設計資料が必要。

## 決定

reikanrm/tomurai のdevを実装に使用する。mainへpush/mergeしない。
ADR・SSOTは同リポジトリ内、説明用の仕様・設計書はJunichiroAita/tomurai-docsへ分ける。
Aitane/dstyle--docsの画面別説明という構成を参考にするが、他プロダクトのコード/業務データ/配信環境/資格情報をそのまま移植しない。
Figmaは使用しない。実際のReact Native Webビルドを仕様サイトへ同梱して表示する。

## 整合性

正本はproduct-requirements/画面catalog/実装。説明サイトへの同期時はソースのcommitとファイルhash、作業ツリーdirtyを記録する。
汚れた作業ツリーのプレビューを、commit済みの内容と偽らない。派生データをサイト側で直接修正しない。
APIとDBの仕様は実装ができ次第追加する。未実装をサンプルから推測して確定扱いにしない。

## 帰結

2リポジトリの差分・同期管理が必要。当初は配信先未設定のためローカルで検証した。既存Vercel配信の修復範囲は下記追補に従う。

## 2026-09-27 追補：iPhone風の資料プレビュー

TOM-25の明示依頼により、仕様サイトの矩形iframeをiPhone風の端末枠へ置き換える。[表示契約](../ssot/docs-preview.md)に沿い、黒い筐体と装飾を資料側だけに置く。アプリの複製や別モックを作らず同じRN Web exportを使う判断は維持。端末装飾はアプリ操作を覆わず、狭幅時も文字縮小なしで再レイアウトする。参照ビルドのhashとdirtyを示し、実機検証や公開の完成と誤認させない。

## 2026-09-27 追補：固定版からの資料配信（TOM-69）

決定者：テックリード・會田 純一朗。Vercelの設定が未追跡の `tools/vercel-build.mjs` を呼び、docs main/778120dがMODULE_NOT_FOUNDで失敗した。利用者は修正・commit/push・再デプロイ・表示確認を承認した。

生成previewをGitへ追加する代わりに、snapshotで固定した公開productコミットをビルド時に取得し、既存のexportと同期を使う。これにより別UIの複製や動くdev先端との版ずれを避ける。配信出力は専用distの許可リストのみ。改行差を正規化した正本hash、実生成HTMLhash、dirty=falseを検証する。

既存アクセス保護・支出プランを変えず、資料用の未接続・合成プレビューとして配信する。実アプリの一般公開、監修、実機合格、GCP構築の承認ではない。[契約](../ssot/docs-preview.md)に受入と境界を記す。

配信調査の補足：ビルド処理とパスワード認証は別docsブランチ `claude/nice-clarke-2seb5z` に存在し、稼働版 `3bd39b2` はそれを使用していた。mainへの統合漏れが原因。既存の認証・テーマ・用語説明・ローディングを統合して維持する。静的ビルドだけの置換による公開範囲の拡大を禁止し、未認証拒否を追加受入にする。
