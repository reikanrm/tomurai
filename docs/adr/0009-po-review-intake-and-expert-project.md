# ADR-0009 — POレビューを差分管理し、専門家ダッシュボードを別プロジェクトで仕様化

- 日付：2026-09-26
- 決定責任者：テックリード・會田 純一朗
- 状態：チケット化/別プロジェクト作成の管理方針を実施。機能詳細はgrill中、実装設計の採用・構築/公開承認ではない
- 対象：TOM-50〜66、既存TOM-2等

## 背景

POレビューには画面変更と、料金・生前利用権・専門家への送信・法人請求の変更が混在する。旧仕様の単純な追記では相反する実装になる。生前モックは共有されたが、画面の初期値やデモの2名死亡確認を本番承認とみなせない。

## 管理上の決定

1. [変更要求台帳](../ssot/po-review-2026-09-26.md)を正本とし、PO要求/観察事実/推薦/確定回答を区別する。
2. TOM-50に対応表を持ち、アプリ側13票を作成。既存TOM-2はモック受領・grill待ちへ更新し、ノート仕様を重複起票しない。
3. ユーザーの明示依頼どおり、専門家ダッシュボードは別のLinearプロジェクトと3つの仕様票に分ける。これは別リポジトリ・マイクロサービス・有料インフラを選定した意味ではない。
4. 年払い15%等の明確な変更要求と、無料/有料の主語・法人請求周期・死後公開条件等の未確定事項を分けてgrillする。予算や公開ゲートは包括承認で補完しない。
5. 仕様の共有理解を確認後、仕様書/設計書/既存SSOTの該当表/コード/検証を1チケット単位で同期する。今回はアプリコードを変更しない。

## 維持する境界

会社が費用負担しても私的情報は閲覧できない。死亡申告/招待/掲載契約だけで共有を広げない。送信同意をアカウント登録同意に含めたことにしない。進捗を感情の良し悪しへ変換しない。Webの見た目への準拠から未監修の古い文言・価格・権限を復活させない。

## 未決・検証

生前利用者範囲/代理入力/死後連携、法人単価と請求条件、専門家相談/ダッシュボードMVP、進捗通知、細かな起動/表示頻度を確認する。全新規票はBacklog。受入は該当するG03/04/06等に加えて料金・認可・重複・誤共有を試験。文書検査や起票成功は、監修・実機・実接続の合格ではない。
