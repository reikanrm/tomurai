# ADR-0010 — POレビューの委任判断と検証境界

日付：2026-09-26。決定責任者：テックリード・會田 純一朗。
状態：委任範囲のローカル実装方針を採用。公開・実接続承認ではない。

## 背景

ADR-0009で起票したTOM-50〜66について、起票後のgrill・推薦・通常判断・文書・実装まで進める指示を受けた。一問ずつの待機で全体を止めず、既決の安全境界とPOの新要求を両立する必要がある。

## 決定

[実装契約](../ssot/po-review-implementation.md)の判断表を採用する。判断の根拠を委任と記録し、POの個別回答や監修承認を捏造しない。各票の実装を否定試験と独立レビューで検証する。価格表示、UI、純粋な判定関数は実装する。未知の法人N・本当の掲載先・クラウド予算・個人情報外部送信の承認・実機実測は補完しない。

Webは視覚参照であり業務の正本ではない。C04は15%OFF、C08はアプリ内パートナー一覧、C06/R08は法人限定本人ノートへ置換する。C19の月額N算定は年額前払いと両立させ、開始済みケースの権利を変えない。全件の実装と実運用完成は別に追跡する。

## 結果

### 2026-09-27：手続き別の管轄選択（TOM-75）

自治体案内の補完として、[管轄選択SSOT](../ssot/municipal-jurisdiction.md)を採用。詳細内の選択と明示適用を分け、起動中はタスク別に保持する。横浜市は区選択を追加し、変更時の確認解除・不正値拒否を行う。全タスクへの住所一括適用は管轄が異なるため採らない。実保存基盤や未監修個別本文の公開をこの操作で代替しない。

### 2026-09-27：手動遷移と招待のローカル検証

最新依頼で導入の手動操作にも演出を追加し、招待は明示回答「ローカルの一連操作を先に実装する」を採用する。[追加SSOT](../ssot/startup-and-invitation-rehearsal.md)に境界を記録。RN標準Animatedを再利用し追加依存なし。招待は既存判定関数を呼ぶメモリ内の合成adapterと明示的な練習画面を追加し、実サービスがない状態で送信/認証/参加完了と偽表示しない。開発/検証ビルド限定、権限切替時破棄、単独有料の未決済承認拒否を維持する。本番API・インフラ・監修・両OS実機の完了承認ではない。

### 2026-09-27 追補：生前ノートの利用対象に関する明示回答

社員本人と招待された家族本人を対象とし、各本人のアカウントで自分自身のノートを管理する、勤務先には内容を公開しない、という個別回答を受けた。これらは委任判断に加えて明示確認済みとする。第1問時点では社員による親の代理入力を別論点として未決にしたが、その後の回答は以下の追補を優先する。[生前ノートSSOT](../ssot/life-notes.md)とTOM-2/TOM-62へ反映する。その他の委任判断・実接続/監修ゲートを一括承認した扱いにはしない。

### 2026-09-27 第2問の追補：依頼された親のノートへの代理入力

利用者の「はい、入力可能にしたいです！」という明示回答により、親本人から頼まれた社員が自分のアカウントから親のノートを代理入力できる方針を採用する。従前の代理入力なしという実装方針をこの範囲で変更する。所有者と入力者を分離し、勤務先非公開・家族参加だけの開示禁止・死後自動公開禁止は維持する。

第2問時点では依頼確認、親アカウントの要否、委任項目・操作、内容確定・撤回・失効を未決とした。依頼確認方法は以下の第3問で更新。現在の認可コードは変更せず、残る詳細確認後に否定試験と実装を追加する。採用方針と実装済みを区別する。

### 2026-09-27 第3問の追補：親本人による入力担当承認

利用者の「必須にする」という回答により、代理入力開始前に親本人が自分のアカウントで対象社員を入力担当として明示承認することを必須とする。社員の自己申告・家族招待だけでの権限付与は認めない。親本人が承認操作できない場合の代替手段は未決。

第3問時点で個々の入力内容を誰が確定するかは未決としたが、以下の第4問で更新する。委任項目・操作・撤回・失効は未決のまま。入力担当への承認を、内容の承認や法的本人確認の完了として扱わない。既存コードの認可は詳細合意まで変更せず、TOM-2/TOM-62で追跡する。

### 2026-09-27 第4問の追補：親本人による下書きの内容確定

利用者の明示回答を受け、社員の代理入力は下書きとし、親本人が内容を確認・承認してから確定する方式を採用する。入力担当承認、内容確定、共有を分け、社員による自己承認や確定に伴う自動共有は認めない。下書きの版と承認対象を対応付け、古い承認による別版の確定を防ぐ。委任項目・操作・撤回/失効・親が承認できない場合の例外は未決として保持し、今回は文書のみを変更する。[詳細正本](../ssot/life-notes.md)。

### 2026-09-27 第5問の追補：項目別の閲覧・下書き委任

利用者の「はい」という明示回答により、親本人が選んだ項目だけ、承認済み入力担当の社員に既存内容の閲覧と変更案の下書き入力を許可する方針を採用する。未選択項目の内容は見せず、他の家族への共有設定変更・確定内容の削除は許可しない。第4問の自己承認禁止・確定と共有の分離を維持する。

全面的なノートアクセスではなく、親が入力を頼みたい内容だけを委任できるようにする。これにより、例えば葬儀の希望の入力は頼むが資産情報は見せない、という選択が可能になる。項目別のサーバー認可・返却データ制限が必要となるが、その実装完了を意味しない。

過去の「委任項目・操作は未決」をこの範囲で更新する。撤回/失効時の扱い、下書き処理、親が承認できない場合の例外は未決。文書のみ更新し、現行認可コードの代理入力拒否を維持。[詳細正本](../ssot/life-notes.md)、TOM-2/TOM-62。

### 2026-09-27 第6問の追補：親本人による取消と内容保持

利用者の「はい」という明示回答により、親本人がいつでも依頼を取り消せる。社員の委任による閲覧・入力を即時停止し、下書きは親側に残して採用・削除を親が選ぶ。確定内容は取消だけでは消さない。第5問までの「撤回と取消時の下書きの扱いは未決」をこの範囲で更新する。依頼をやめる権利と記録の消失を分離する判断である。

通常の受取人共有とは別の操作であり、無期限保存や他の独立した権限の変更は承認しない。期限/資格喪失等による自動失効・親が承認できない場合の例外は未決、文書のみ更新して現行コードの代理入力拒否を維持。[詳細正本](../ssot/life-notes.md)、TOM-2/TOM-62。

### 2026-09-27 第7問の追補：初期版は承認代行なし

利用者の「はい」という明示回答により、初期版では社員・運営による承認の代行を設けない。操作の説明・補助は可能だが、入力担当の指定と内容の承認は親本人が行う。本人が承認できない場合は開始・確定を保留する。操作補助と承認主体を分け、本人の意思と異なる内容が確定することを防ぐ。

過去の「承認できない場合の例外は未決」を初期版の範囲で更新する。例外対応は別途仕様と監修後に追加を判断する。永久の対象外や自動判定、保留だけによる削除/共有は採用しない。残る自動失効等は未決で、現行認可コードは変更しない。[詳細正本](../ssot/life-notes.md)、TOM-2/TOM-62。

### 2026-09-27 第8問の追補：資格喪失による失効と再承認

利用者の「はい」という明示回答により、社員または親が法人向け生前機能の利用資格を失った場合は、代理入力の委任を失効させる。既存ノート・下書きは消さず、親本人の閲覧・共有撤回・削除を維持する。資格が復活しても自動再開せず、親本人が入力担当と対象項目を再承認する。資格の復活を過去の委任の再同意と解釈しないための判断である。

過去の「資格喪失による自動失効は未決」をこの範囲で更新する。別の有効資格、本人所有、独立した受取人共有を混同せず、無期限保存や内容の自動確定/共有は追加承認しない。固定の有効期間は未決、文書のみ更新して認可コードは現行拒否のまま。[詳細正本](../ssot/life-notes.md)、TOM-2/TOM-62。

### 2026-09-27 第9問の追補：30日間の委任・自動更新なし

利用者の「はい」という明示回答により、親本人の入力担当承認から30日間を委任の有効期間とし、自動更新しない方針を採用する。期限後は委任による閲覧/入力を停止するが、ノート/下書きは既存の保存条件で保持する。再開には親本人が入力担当・対象項目を再承認し、新しい承認から30日間とする。

委任が放置されたまま継続しないための判断であり、継続する場合に本人の再承認が必要になる負担を受け入れる。操作による期限延長はしない。先行する取消/資格喪失を優先し、期限内であることを復活条件にしない。内容確定、独立した共有、所有権、保存期間は別のまま維持する。

過去の「固定の有効期間は未決」を更新。サーバー承認時刻＋30×24時間の境界検査を設計するが、今回は文書のみで現行認可コードは代理入力を拒否したまま。実接続・監修・公開は承認していない。[詳細正本](../ssot/life-notes.md)、TOM-2/TOM-62。

本番APIがない画面は送信・保存完了を表示しない。インフラ費用の差戻しを回避するための無断構築をしない。既存TAKTのmock実行や単体テスト成功を、本番認可・保存・通知・監修・物理端末の代用にしない。未充足G01〜06は引き続き公開を止める。
