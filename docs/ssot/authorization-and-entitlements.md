TOM-70で[代理入力の合成練習](life-delegation-rehearsal.md)のみ追加する。通常のlife-accessと実APIの権限は開放せず、以下の代理入力「拒否/未実装」は通常機能に適用する。練習ロール/時計は本番認可ではない。

TOM-50/62の最新変更は[生前ノート](life-notes.md)・[専門家](expert-dashboard.md)を参照。旧「有料グループ所属ならノート編集可」は廃止し、法人資格と本人所有を要件にする。第2問で親から依頼された社員の代理入力方針を採用、第3問で親本人アカウントによる入力担当承認を必須化した。第4問で代理入力は下書きとし、親本人の確認・承認後に確定する方式を採用。第5問で親の選択項目の既存内容閲覧・下書き入力だけに限定し、未選択項目の内容、共有設定変更・確定内容削除は許可しない。第6問で親による任意取消、委任の閲覧/入力即時停止、下書きは親側に残し採用/削除を本人選択、確定内容は保持を採用。第7問で社員/運営の承認代行を初期版に設けず、操作補助と本人承認を区別し、本人が承認できなければ開始/確定を保留とした。第8問で社員または親の資格喪失による委任失効と、資格復活後の本人再承認必須を採用。ノート/下書きは保持し本人の閲覧/共有撤回/削除を維持する。第9問で委任は本人の入力担当承認から30日間・自動更新なし。満了後は委任の閲覧/入力を停止して記録を保持し、再開は本人が担当/項目を再承認する。利用で期限を延長せず、取消/資格喪失が先ならその時点で失効する。本人所有と入力担当・内容確定・共有を分離し、今回の決定記録だけでは現行認可を緩めない。API未接続の開発切替で本物の資格を付与しない。

## 共通の判定順

TOM-71の最新依頼で[製品用ノートサービス](life-notes-product.md)に委任の照合を実装する。上記TOM-70の通常機能未実装は前段の履歴。既存life-accessの本人所有を緩めず、新サービスが対象社員/項目/期限/現在資格を別に検証する。UIの役割切替を本番の認証としない。実HTTP/認証/永続DBの結合検証は未達。

認証→アカウント有効性→対象グループの承認済み在籍→操作対象の所有/共有/同意→操作ごとの利用権。
本人所有・直接共有ノートはグループ共同記録と別の境界で検査する。
支払者、質問回答担当、記録作成者、共有指定先、法人担当者を一つの「管理者」ロールへ統合しない。
判定はサーバーで行い、UI表示・LINE連携・推測困難なIDを認可の代わりにしない。

| 対象・操作 | 許可の条件 | 禁止・例外 |
|---|---|---|
| 質問の私有下書き | 指定回答担当本人だけ | 支払者・家族・法人・運営の通常画面からは読めない |
| 質問確定/訂正 | 指定回答担当1名、版の一致 | 競合は明示、他の家族が上書き不可 |
| 確定済み共同情報/タスク | 在籍とグループ利用権。無料は固定2タスクだけ詳細を返す | 有料タスク本文をAPI/キャッシュ/読み上げ/LINEへ漏らさない。完了で無料枠を回転しない |
| 通常の担当・進捗更新 | 在籍・対象タスク操作権・版一致 | 家族間で通常操作は同権限。法的当事者と担当者は別 |
| 家族招待・参加 | ログイン、単回リンク、合言葉、既存1名の承認 | 人数による上限なし。期限7日、取消/再利用/同時利用/重複参加を拒否。レート制限は人数上限とは別 |
| 単独→家族利用 | 支払者が差額と適用日に同意し、権利の確定後に2人目の参加を確定 | 招待だけで請求しない。家族プランは3人目以降の追加料金なし |
| 支払手段・引継ぎ | 支払者本人の再認証、新支払者の明示同意 | 家族全員へのカード情報開示・流用なし |
| 香典記録 | グループ共同利用権。初期項目は送り主氏名・金額だけ | 失効後は既存の共有範囲で閲覧のみ。AI参照は記録作成者の同意が必要 |
| ノート本人編集 | 本人所有、本人IDに一致する有効な法人資格（社員本人または招待家族本人） | 一般B2Cの有料権利だけでは不可。支払者である必要はない。下記の代理入力とは別の権限 |
| 親のノートの代理入力（TOM-71サービス、実API未接続） | 親本人が自分のアカウントで対象社員を入力担当として承認することが必須。社員は自分のアカウントで親の選択項目だけ既存内容を閲覧し、変更案を下書き入力。親本人の内容確認・承認後に確定。親はいつでも取消可能、委任の閲覧/入力は即時停止。下書きは親側に残し採用/削除を本人選択、確定内容は取消だけで消さない。社員/親の資格喪失で委任失効、資格復活後も担当/項目の本人再承認が必要。ノート/下書き保持、本人の閲覧/共有撤回/削除を維持。委任は本人の入力担当承認から30日間・自動更新なし。満了後は委任の閲覧/入力を停止して記録を保持し、再開は本人が担当/項目を再承認する。利用で期限を延長せず、取消/資格喪失が先ならその時点で失効する。 | 既存life-accessは拒否を維持、新サービスは現在主体/資格epoch/委任/項目/対象版を検査する。初期版は社員/運営の承認代行なし、操作補助を本人承認とみなさず承認不能時は開始/確定保留。未選択項目の内容非開示、社員の自己承認・共有設定変更・確定内容削除は不可。確定による自動共有なし。自己申告/家族招待だけで有効にせず、所有者を変更しない |
| ノート閲覧 | 本人または本人が指定した項目・受取人 | 受取人は無料でも閲覧可、編集不可。家族参加/死亡登録だけで公開しない |
| ノート撤回/削除 | 本人。法人資格失効後も本人の閲覧・撤回・削除を維持 | 課金切替で所有者・共有先を変えない。未監修機微項目・ログイン情報の収集は有効化しない |
| 専門家への相談共有 | 宛先・送信項目を本人が確認し明示同意。受領先の組織/担当/現在の許可/期限が有効 | 登録/掲載料/家族承認だけで送信しない。家族DBやノート/AIの自動添付なし。外部リンク遷移は受領成功ではない |
| AI質問 | 有効な対象グループを本人が選択、必要な同意、枠予約成功 | 他グループ・他人の私有情報・他人の会話にアクセス不可。読み取りのみ |
| LINE通知 | 連携本人・送信同意・送信直前の在籍/担当/状態確認 | 本文は一般的案内、個人名/金額/タスク名/会話内容を通知本文に含めない |
| 法人画面 | 当該法人の認証/MFAと担当ロール、契約上必要な最小情報 | 家族の回答・タスク・ノート・香典・会話は不可。他社のケースは不可 |
| 運営支援 | 明示された支援目的と最小アクセス、監査 | 通常の全私有記録閲覧/本人なりすましは不可。紛争による恒久削除は自動化しない |
| グループ全体削除 | 2人以上は申請＋別の1名確認、30日回復期間 | 本人アカウント削除・本人退会とは別 |
| 本人アカウント削除 | 本人再認証、アクセス即時失効、本人由来データの削除処理 | 支払者引継ぎ待ちにしない。他人の独立記録は削除しない。派生情報は再評価 |

## 人数上限なしを実装する条件

- membershipを独立したレコードとして扱い、groupに巨大なメンバー配列を保存しない。
- サーバー側ページ分割・安定ソートを使用する。全件取得をアプリ起動の必須条件にしない。
- 10人などの固定値で参加を拒否する分岐を作らない。通知の配信制御は利用人数制限に転用しない。
- 1/2/3/10/100人以上、同時招待・取消・再参加の合成ケースを用意する。これは試験規模であって商品上限ではない。
- βAIは家族共通50成功回答/月、本人10/日・家族20/日の暫定値。人数・再参加・プラン変更で枠を補充しない。正式枠はG01で別途承認。

## 必須の否定テスト

他グループIDへの置換、脱退/削除/同意撤回直後、キャッシュ/LINE/AI経由、法人/支払者の権限混同をすべて拒否する。
更新時はrevisionとoperation IDを検証し、競合時の黙った上書き・二重課金・二重送信を防ぐ。
承認仕様の受入試験1–5、8、15–21をAPIと実機で行う。現時点では未実行。
