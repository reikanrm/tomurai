# 認可と家族利用権の境界

2026-09-26。決定責任者：テックリード・會田純一朗。承認仕様 C03–C06 / R01–R14 / R20–R24 / R32 / R37 / R43 の実装契約。
これはサーバー実装・セキュリティ試験の完了証拠ではない。

TOM-38/39のローカル表示判定・固定無料ID・開発専用切替は[追加仕様](access-preview.md)。本番認可をクライアントへ移す変更ではない。

## 共通の判定順

認証→アカウント有効性→対象グループの承認済み在籍→操作対象の所有/共有/同意→操作ごとの利用権。
本人所有・直接共有ノートはグループ共同記録と別の境界で検査する。
支払者、質問回答担当、記録作成者、共有指定先、法人担当者を一つの「管理者」ロールへ統合しない。
判定はサーバーで行い、UI表示・LINE連携・推測困難なIDを認可の代わりにしない。

| 対象・操作 | 許可の条件 | 禁止・例外 |
|---|---|---|
| 質問の私有下書き | 指定回答担当本人だけ | 支払者・家族・法人・運営の通常画面からは読めない |
| 質問確定/訂正 | 指定回答担当1名、版の一致 | 競合は明示、他の家族が上書き不可 |
| 確定済み共同情報/タスク | 在籍とグループ利用権。無料は固定2タスクだけ詳細を返す | 有料タスク本文をAPI/キャッシュ/読み上げ/LINEへ漏らさない。完了で無料枠を回転しない |
| 通常の担当・進捗更新 | 在籍・対象タスク操作権・版一致 | 家族間で通常操作は同権限。法的当事者と担当者は別 |
| 家族招待・参加 | ログイン、単回リンク、合言葉、既存1名の承認 | 人数による上限なし。期限7日、取消/再利用/同時利用/重複参加を拒否。レート制限は人数上限とは別 |
| 単独→家族利用 | 支払者が差額と適用日に同意し、権利の確定後に2人目の参加を確定 | 招待だけで請求しない。家族プランは3人目以降の追加料金なし |
| 支払手段・引継ぎ | 支払者本人の再認証、新支払者の明示同意 | 家族全員へのカード情報開示・流用なし |
| 香典記録 | グループ共同利用権。初期項目は送り主氏名・金額だけ | 失効後は既存の共有範囲で閲覧のみ。AI参照は記録作成者の同意が必要 |
| ノート本人編集 | 本人所有、本人が参加する有効な有料グループが1つ以上 | 支払者である必要はない。他人の代理編集はしない |
| ノート閲覧 | 本人または本人が指定した項目・受取人 | 受取人は無料でも閲覧可、編集不可。家族参加/死亡登録だけで公開しない |
| ノート撤回/削除 | 本人。失効後も維持 | 課金切替で所有者・共有先を変えない。POモック未確定の項目は作らない |
| AI質問 | 有効な対象グループを本人が選択、必要な同意、枠予約成功 | 他グループ・他人の私有情報・他人の会話にアクセス不可。読み取りのみ |
| LINE通知 | 連携本人・送信同意・送信直前の在籍/担当/状態確認 | 本文は一般的案内、個人名/金額/タスク名/会話内容を通知本文に含めない |
| 法人画面 | 当該法人の認証/MFAと担当ロール、契約上必要な最小情報 | 家族の回答・タスク・ノート・香典・会話は不可。他社のケースは不可 |
| 運営支援 | 明示された支援目的と最小アクセス、監査 | 通常の全私有記録閲覧/本人なりすましは不可。紛争による恒久削除は自動化しない |
| グループ全体削除 | 2人以上は申請＋別の1名確認、30日回復期間 | 本人アカウント削除・本人退会とは別 |
| 本人アカウント削除 | 本人再認証、アクセス即時失効、本人由来データの削除処理 | 支払者引継ぎ待ちにしない。他人の独立記録は削除しない。派生情報は再評価 |

## 人数上限なしを実装する条件

- membershipを独立したレコードとして扱い、groupに巨大なメンバー配列を保存しない。
- サーバー側ページ分割・安定ソートを使用する。全件取得をアプリ起動の必須条件にしない。
- 10人などの固定値で参加を拒否する分岐を作らない。通知の配信制御は利用人数制限に転用しない。
- 1/2/3/10/100人以上、同時招待・取消・再参加の合成ケースを用意する。これは試験規模であって商品上限ではない。
- βAIは家族共通50成功回答/月、本人10/日・家族20/日の暫定値。人数・再参加・プラン変更で枠を補充しない。正式枠はG01で別途承認。

## 必須の否定テスト

他グループIDへの置換、脱退/削除/同意撤回直後、キャッシュ/LINE/AI経由、法人/支払者の権限混同をすべて拒否する。
更新時はrevisionとoperation IDを検証し、競合時の黙った上書き・二重課金・二重送信を防ぐ。
承認仕様の受入試験1–5、8、15–21をAPIと実機で行う。現時点では未実行。
