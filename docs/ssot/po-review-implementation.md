## 実装と公開の区別

画面・ドメイン・契約・合成データのローカル試験は進める。インフラ予算/実認証/保存・同期・実通知/専門家実データ/法務監修/実機試験は未充足。価格Nや掲載先を架空値で埋めず、機能は未設定を明示する。設定されていない外部処理を成功扱いしない。

## ハーネス

各子票で「要件→決定→否定試験→実装→独立レビュー→再検証」を記録。TAKTの既存small-change設計と同じ停止境界を採用するが、mock providerの終了を実装証拠にしない。テストは抽選/時刻/認可/料金の実動作を検証する。`npm test`、`npm run check`、型検査、Webビルドと画面確認を統合時に実施。実行していない実機・監修・外部疎通は合格にしない。
