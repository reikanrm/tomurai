# 共通カレンダー / TOM-37

決定責任者：テックリード・會田 純一朗。2026-09-26。C01/C02/C07、R15/R17/R19/R48。コード変更より先に記録。

## 対象と操作

死亡日（オンボーディング）と四十九日法要予定日（任意設定）を共通の `CalendarDateField` で扱う。タスクを並べる月間画面、外部カレンダー、祝日・六曜は追加しない。

- 紙色、深緑、Noto Sans JP、細い罫線を継承。余白のある月表示、深緑の選択日、今日の輪郭と小さな印を使う。日付は大きく、操作説明は控えめにする。円相ロゴの変更なし。
- 月送り・戻し、年月見出しから年の直接入力と12か月選択、現在の月へ戻る操作。月表示の変更だけでは回答を変更しない。
- 日曜始まりの7列。日英の曜日・月・読み上げ用の完全な日付。カレンダーの日付はボタンとしてTab/Enter/Spaceで選択可。色だけでなく選択状態・今日のラベルを付ける。
- 「日付を入力」に切り替えた場合はYYYY-MM-DDを直接入力できる。選択日/直接入力は親の下書きへ渡し、既存の最終確認・適用操作を維持する。
- 未入力は未入力のまま。カレンダーが今日を表示しても、今日を自動回答にしない。「わからない・あとで確認」「予定日を未定に戻す」は維持する。
- 死亡日はJSTの今日以前。法要予定日は、死亡日が判明していればその日以降（未来は可）。無効な日付/制約外の日付は選択不可。直接入力も既存の親画面の検証で拒否する。表示できる暦日は4桁の西暦0000〜9999（既存ISO値との互換）、利用年齢や死亡からの期間の新たな制限は設けない。
- 暦日は時刻に変換して保存しない。D+6/D+48や相続期限の意味を変えない。法要の目安を勝手に予定日へ入れない。

## 実装・検証

日付計算は純粋な `date-picker.ts`、表示と開閉/表示月は共通部品、入力制約/適用は呼出し側。React Native標準部品と既存SVGだけを使い追加依存なし。ブラウザー専用のdate inputを正本としない。

月末、うるう年、12月→1月、日曜配置、上下限、不正値、未入力を自動試験。日英・狭い画面・キーボード・未定・再編集をブラウザー確認。両OS実機/読み上げは別途G06で記録し、未試験を合格にしない。
