## 共同状態の境界

- 認証済み主体IDは将来のサーバー認証アダプターだけが生成。クライアントのrole、payer、entitlement、memberCountを受け取らない。
- repositoryは同一グループの状態/現在のmembership/利用権/操作記録を原子的に読む・更新する。readも在籍失効と整合する。テスト用メモリ実装を永続化と呼ばない。
- 確定回答、GuidancePlan、RitualWorkHistory、TaskProgress、burialBeforeCompletion、EventDates、固定無料2IDを同じrevisionで保持。回答を訂正して非表示になったタスクの進捗/担当は消さない。
- 気分やケア選択は保存しない。私有下書き・個人の閉じた節目/表示設定は共同状態と分離する。これらの保存APIは後続で本人認可を設ける。家族1人の閉じる操作を全員へ同期しない。
- confirmAnswersは指定回答担当だけ。許可済み質問の回答を検証し、サーバー側でplanと候補を導出する。無料2IDは初回確定時のみ選定し、nullと確定済み空配列を区別する。
- updateTaskは承認済み家族の対象タスクのみ。対象権利・存在・任意性・担当者の在籍を確認。法要本体の完了はcompletionKeyに対応する項目だけを更新し、任意のplan書換えを許可しない。納骨取消前の分岐も保持する。
- readTaskProjectionは現在閲覧可能なタスクだけ返す。無料の隠しタスク本文/担当/日付、全progress、raw answers、私有下書きは返さない。候補総数と公開装飾は機微情報の代わりに扱わない。

## 更新・再送

expectedRevisionとoperationIdを必須にする。競合は明示的エラーで、無言マージしない。同じ主体/グループ/操作ID・同じ正規化payloadの再送は1操作、別payloadでの再利用は拒否。再送時も現在の認可と対象権利を再確認し、古い結果で権限失効を回避しない。原子的に状態と操作受領記録を保存し、失敗は両方をロールバックする。結果は操作ID・改訂等の最小受領情報とし、過去の非公開snapshotを再送しない。

## LINE通知の契約

- 本人1対1連携、同意、有効アカウント/在籍、対象利用権、本人担当、未完了、最新の確認済期限を送信直前に確認する。未担当・不明な期限は自動推測しない。実機用pushは別途設計/同意が必要。
- 期限30/7/1日前、当日、翌日だけ。JSTの設定時刻（初期09:00）から当日内で評価し、前日分の遅延ジョブを翌日に送らない。設定/連携/対象タスク登録より前の通知イベントは補送しない。
- 1人1日最大1まとめ。複数グループでも1通にまとめる。後続キューの一意キーは本人ID+JST日付+task-digestで原子的予約。メンバー人数を配信上限に転用しない。
- 固定の一般文だけを送る。故人名、タスク名、金額、グループ名、会話を引数として受け取らない。任意法要を法的期限へ変換しない。法要後相続注意、節目メッセージ、AI/課金通知は本契約に混ぜない。
- 監修未完了の言語/本文は配信候補にしない。未連携/停止/権限失効/対象なしは送信なし。設定エラーもfail closed。
- 状態はpending / accepted / rejected / uncertainを区別。受付成功は到達・既読ではない。送信不明時に別のキーで再送しない。LINEの同一retry key・有効期間と同じpayloadを守り、範囲外は運営確認。日次一意キーはLINE retry keyそのものとは分ける。
- 純粋関数は分散ロックや配信を保証しない。キュー・Webhook署名・リンクnonce・token検証・レート制限・失敗監視・同意画面は実接続前に必須。
