# TOM-58 — 相談導線と未接続の受領状態

2026-09-26。決定責任者：テックリード・會田 純一朗。C08 / R10 / R43、G02 / G04 / G06。[委任実装契約](po-review-implementation.md)・ADR-0010の実装詳細を、コードより先に記録する。

## 分岐

1. 掲載許可/期間/確認済みHTTPS問い合わせ先を再検証。不成立なら相談導線を無効化。
2. 未登録ならTomurai登録案内。認証API未接続の現段階では準備中を明示し、登録完了にしない。有料化を求めない。
3. 登録済みで有料利用権ありなら、本人が「問い合わせ先を開く」を押した時だけ確認済みURLへ進む。URLは登録値のまま、質問回答・故人名・ノート・AI会話等のqueryを付けない。外部サイトを開くことと相談受付成功を区別する。
4. 登録済み無料なら宛先と送信予定項目を確認する。登録同意は送信同意として使わない。今回は連絡先/相談本文の項目・保存期間が未確定であるため入力欄を作らず、予定メタデータ（選択した相談先のID、受付識別子）の説明のみ。実受付APIは接続せず、確認後も未送信・準備中と表示する。

個人有料・家族有料・法人支援・失効の利用権評価は呼出元が担い、画面の表示だけで有料化しない。Appは実認証未接続のため `registered=false` を渡す。既に登録済みの人へ二重登録を要求する分岐を作らない。

## メタデータ受領契約（実送信ではない）

`draft / unavailable / pending / uncertain / accepted` を分離する。

- `beginConsultation` は掲載有効・登録済み無料・明示的送信同意・有効な操作ID・受付接続が全部成立した場合だけ `pending` を返す。UIは受付接続なしを固定し、通信を呼ばない。
- `pending / uncertain / accepted` の同じ状態へ二度目の開始操作を適用しても新しい受付識別子を作らない。結果不明を未送信と断定せず、自動再送しない。
- `accepted` はリクエストID・宛先IDが一致し、受付ID・UTC受領日時を持ち、信頼できる検証処理が真と確認した受領証跡だけで成立する。レスポンスの `accepted=true` だけでは成立しない。検証処理未指定/例外は失敗側。
- 同意撤回は今後の送信許可を外す。送信開始後なら `uncertain` を保持し、送信済みを取り消した/相手のデータを消したと偽表示しない。撤回後でも検証済み受領証跡で事実を確認することは、再送とは別。
- 掲載失効/登録解除/利用権変更は開始時に再評価する。家族情報の添付、課金、実受付、取り消しAPI、保存/削除は実装しない。

## 検証と残る条件

Appは選択IDを現在のregistryから毎回再解決し、同じIDが複数ある場合は相談シートを表示しない。登録済み状態は実認証が接続されるまでfalse。ネイティブscheme登録・起動中の招待URL受信・実招待消費は別の未接続条件として残す。

テストは未登録/無料/有料/失効、掲載終了、同意欠損、未接続、二重操作、通信断、撤回、偽/不一致受領証跡を先行して失敗させる。日英UIと外部URL無改変・外部起動失敗を部品試験する。実登録・実相談送信・連絡先項目・保存期間・法務/英語確認・両OS実機は未充足であり、単体試験をG02/G04/G06の代用にしない。
