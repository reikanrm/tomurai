# 家族招待のローカル実装契約（TOM-61）

2026-09-26。決定責任者：テックリード・會田 純一朗。C05 / R02 / R03 / R11 / R13 / R43。
[委任判断](po-review-implementation.md)・[ADR-0010](../adr/0010-delegated-po-review-implementation.md)の補足。コードより先に記録する。新たな共有権限や課金同意の追加ではない。

## 画面の境界

ホームの「家族と分担」から家族画面へ進む。承認済み家族は招待準備の説明を開ける。未承認の本人には承認待ちと説明し、招待操作を許可しない。招待/参加/承認APIは未接続であり、リンク、合言葉、本人情報、申請件数、成功受領書を生成しない。操作後も「準備中・リンクは発行されていません」と表示する。家族一覧や申請が0件と断言せず、取得できないことを明示する。

招待は死後の共同作業への参加で、生前ノートの公開とは別。人数上限なし・3人目以降の人数追加料金なしを維持する。単独有料の場合は支払権限者へプラン確認、その他の家族へ契約者への依頼案内を表示する。いずれも、この画面から実送信・購入・利用権付与はしない。

## 純粋なドメイン判定

- 入力contextは将来サーバーで検証した本人、有効アカウント、現在の当該グループ在籍、利用権、支払権限者、レート制限結果を表す。HTTPの自己申告や `AccessPreview` をこのcontextへコピーして認可してはならない。現実装は合成テスト用で認証アダプターではない。
- 招待作成/取消/承認は現在の承認済み家族だけ。作成時には7日（168時間）の期限と版付きメタデータを提案するだけで、URL・秘密を生成しない。
- 参加申請には検証済みトークン、別経路の合言葉照合、ログイン、試行制限、未参加を必要とする。成功すると当該招待をその申請者1名に予約して承認待ちへ進める。別人への転送/多重申請で予約を移動しない。
- 既存家族1名の承認前には参加確定しない。申請者自身の承認、別家族、退会済み/未承認の承認者、無効アカウント、既に参加した申請者を拒否する。
- 作成から7日経過した招待は、申請時も承認時も期限切れ。取消/使用済みの再使用は不可。承認待ちで期限を過ぎた場合は新しい招待が必要。期限不明を有効にしない。
- 招待作成時または承認時に単独有料の2人目以降となる場合は、支払権限者の見積/適用への明示同意と、家族利用権の有効化の両方が必要。clientの「同意済み」だけでは確定しない。同意証跡は対象グループ/招待/現在支払者/見積ID/承認時刻を照合。プラン状態が変更された場合は確認し直し、無断増額で解決しない。
- invitation revision と group revision の両方を期待値と照合する。認可を先に検証し、失効した本人に古い成功結果を返す経路を設けない。同時リクエストを実際に防ぐには、サーバーでメンバー/招待/権利/改訂を同一トランザクションで読み、一意制約とcompare-and-swapで提案を保存する必要がある。純粋関数を排他制御と呼ばない。
- すべての結果で課金/ノート共有は変更なし。参加確定案は当該申請者の在籍有効化だけ。支払者/回答担当/ノート受取人にはしない。人数を理由に拒否する分岐は作らない。

## 後続の接続条件

暗号学的乱数によるトークン、秘密のハッシュ保管、定数時間比較、URLログ抑止、試行制限、本人認証、サーバーの現権限読み出し、原子的な保存と再送receipt、リンク/合言葉の別経路案内を接続前に実装する。UI操作を保存完了・送信済みと表示しない。

G02/G04/G06を残す。実アカウント2名でPixel/iPhoneのリンク受取→ログイン→申請→別人承認→担当分担、取消/期限切れ/並列参加を検証するまで、本当の家族招待の完成とはしない。
